# QMS REST / WebSocket API Contract (v1)

This is the human-readable contract shared by the backend and the frontend.
The machine-readable OpenAPI document is generated by the running backend at
`/v3/api-docs` (Swagger UI: `/swagger-ui.html`). If the two disagree, the code
and generated OpenAPI win and this file must be corrected.

Base path: `/api/v1`. All timestamps are ISO-8601 UTC instants (`2026-10-22T02:15:00Z`).
Business dates (`yyyy-MM-dd`) are evaluated in the site's time zone (default `Asia/Manila`).

## Conventions

### Authentication
* Staff users: `Authorization: Bearer <accessToken>` (JWT, default lifetime 15 min).
* Kiosks and queue displays: `X-Device-Key: <device api key>` (issued per device, shown once).
* Site-to-central synchronization: `X-Site-Key: <site sync key>`.

### Error body (all 4xx/5xx)
```json
{ "timestamp": "...", "status": 409, "error": "Conflict", "code": "INVALID_TRANSITION",
  "message": "Ticket A-012 cannot be completed from status WAITING", "path": "/api/v1/tickets/.../complete",
  "fieldErrors": [ { "field": "reason", "message": "must not be blank" } ] }
```
`code` values used by the UI: `VALIDATION_FAILED`, `NOT_FOUND`, `FORBIDDEN`, `UNAUTHORIZED`,
`INVALID_TRANSITION`, `CONFLICT`, `ACCOUNT_LOCKED`, `RATE_LIMITED`, `PASSWORD_CHANGE_REQUIRED`, `INTERNAL_ERROR`.

### Paged responses
```json
{ "content": [ ... ], "page": 0, "size": 20, "totalElements": 135, "totalPages": 7 }
```
Query params `page` (0-based) and `size` (max 200).

## Auth

| Method | Path | Body | Response |
|---|---|---|---|
| POST | `/auth/login` | `{username, password}` | `TokenResponse` |
| POST | `/auth/refresh` | `{refreshToken}` | `TokenResponse` (refresh token rotated; see note below) |
| POST | `/auth/logout` | `{refreshToken}` | 204 |
| GET | `/auth/me` | – | `Me` |
| POST | `/auth/change-password` | `{currentPassword, newPassword}` | 204 |

```ts
TokenResponse = { accessToken: string; refreshToken: string; expiresIn: number /*seconds*/; user: Me }
Me = { id: string; username: string; fullName: string; mustChangePassword: boolean;
       permissions: string[];             // union of all permissions (see list below)
       assignments: Assignment[];
       sites: { id: string; code: string; name: string }[] }   // sites the user may act on
Assignment = { roleCode: string; roleName: string; scopeType: 'NATIONAL'|'REGION'|'SITE';
               regionId?: string; regionName?: string; siteId?: string; siteName?: string }
```

Refresh tokens are single-use. Re-presenting a token that was rotated less than 60 s ago, while its
replacement has not been used, is treated as a lost response (for example a reload during the refresh):
a new pair is issued and the unused replacement is cancelled. Any other reuse revokes all of the
user's refresh tokens.

Password policy: min 12 chars, at least one upper, lower, digit. After 5 failed logins the
account is locked for 15 minutes (`ACCOUNT_LOCKED`). Login is also rate-limited per IP (`RATE_LIMITED`, HTTP 429).

Access tokens carry the sign-in session id (`sid`). A request with a token whose session was ended
(sign-out, admin revoke, password change or reset, refresh-token reuse) gets 401 even before the
token expires. `Me` includes `idleTimeoutMinutes` (`QMS_IDLE_TIMEOUT_MINUTES`, default 30, 0 = off):
the portal warns one minute before and then signs out an inactive user.

### WebSocket (STOMP over native WebSocket)
* Endpoint: `/ws` (use `wss://` behind TLS).
* Topic: `/topic/sites/{siteId}/queue`.
* Payload: `{ type: 'TICKET_CALLED'|'TICKET_RECALLED'|'QUEUE_CHANGED'; siteId; displayNumber?; counterName?; serviceName?; at }`.
* Messages carry no personal data. Clients should re-fetch the board/snapshot on `QUEUE_CHANGED`
  and also poll every 15 s as a fallback (automatic recovery after network interruption).

`qms_sync_push_entries_total{result}`, `qms_report_runs_total{status}`, plus standard JVM, HTTP, HikariCP
